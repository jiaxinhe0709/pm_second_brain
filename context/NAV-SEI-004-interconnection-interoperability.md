# Interconnection and Interoperability

## Purpose

This section groups customer entry-point management and the external connectivity required for Sage to exchange with the Spanish public solution and other qualifying private platforms.

The customer and exchange PRDs remain authoritative. This page provides a navigation and ecosystem view.

## Capability coverage

| Capability from the Phase 3 assessment | Authoritative document | Current treatment |
|---|---|---|
| Public-solution connection | [Exchange — Interoperability, Routing and Transformation](https://confluence.sage.com/pages/viewpage.action?pageId=866148656) | Covered; reuses Phase 1 capabilities where fit |
| Private-platform connection and interconnection | [Exchange — Interoperability, Routing and Transformation](https://confluence.sage.com/pages/viewpage.action?pageId=866148656) | Covered at product/solution level; bilateral evidence remains required |
| Customer onboarding, entry point, migration and offboarding | [Customer — Onboarding, Entry Point and Migration](https://confluence.sage.com/pages/viewpage.action?pageId=866148655) | Covered |
| Interconnection request and statutory operating period | [Exchange — Interoperability, Routing and Transformation](https://confluence.sage.com/pages/viewpage.action?pageId=866148656) | Covered using the applicable one-month process and interim public route |
| Resilience while a platform or connection is unavailable | [Operations — Resilience, Support and Reconciliation](https://confluence.sage.com/pages/viewpage.action?pageId=866148658) | Covered; alternative delivery must follow legal and lifecycle rules |
| API, sandbox and conformance experience for third-party platforms | Phase 3 roadmap decision | Candidate standalone PRD |
| FACe/FACeB2B, Peppol and international B2B | Phase 3 roadmap decision | Adjacent propositions, not assumed baseline requirements |

## Boundary and open decisions

- A document can support multiple categories but has one authoritative Confluence location. Cross-links expose shared coverage without duplicating requirements.
- Peppol compatibility is not currently evidenced as a Spanish private-platform operator requirement.
- A third-party integration/developer-experience PRD should be created only if Sage commits to an externally consumable API, sandbox, documentation and conformance service.
