# Contributing

## Document workflow

1. Create a short-lived branch.
2. Copy the appropriate file from `templates/`.
3. Assign a unique, permanent document ID.
4. Open a draft pull request early.
5. Obtain the required product and engineering reviews.
6. Merge after automated checks pass.

## Rules

- Keep one PRD or feature proposal per Markdown file.
- Treat `main` as the approved source of truth.
- Use pull-request comments for substantive review.
- Never commit credentials or access tokens.
- Do not edit generated Confluence content directly.
- Mark superseded documents in front matter; do not delete their history.
