Executive Summary & Context
Connecting directly to external government networks—specifically the Spanish State Tax Administration Agency (AEAT) public e-invoicing infrastructure—presents inherent operational risks including network timeouts, unannounced gateway maintenance, and unexpected schema changes.
Because our onboarding product is a
Developer-First API Layer
with an optional downstream UI, the API must handle errors predictably. It must gracefully isolate external network instability from client-side integration bugs. This specification document defines the error taxonomy, response schemas, and automatic retry states required for
Phase 1 (Spain Public Platform Onboarding)
.
Onboarding Error Taxonomy
To ensure clear developer communication, all onboarding pipeline errors must be classified into one of three execution categories:
1. Synchronous Validation Errors (Client-Side / 4xx)
These occur during the initial data capture or certificate upload phases. They represent structural invalidity in the payload provided by the client application. The API must reject these requests immediately without making downstream network requests.
Invalid NIF/NIE Format (ERR_INVALID_TAX_ID):
ERR_INVALID_TAX_ID
The provided tax identifier fails the regex check for standard Spanish NIF/NIE structures.
Malformed Digital Certificate (ERR_CERTIFICATE_CORRUPTED):
ERR_CERTIFICATE_CORRUPTED
The cryptographic payload uploaded via the multipart endpoint cannot be parsed as a valid X.509 certificate.
Expired Certificate (ERR_CERTIFICATE_EXPIRED):
ERR_CERTIFICATE_EXPIRED
The internal timestamp configuration reveals the certificate validity period (
NotAfter
) has passed.
2. Asynchronous Transient Errors (Retryable / 5xx)
These occur after a valid payload has been submitted and our engine attempts to register the corporate profile with the Spanish Public Platform network. These failures are environmental and temporary.
AEAT Gateway Timeout (ERR_GATEWAY_TIMEOUT_504):
ERR_GATEWAY_TIMEOUT_504
The public platform endpoint fails to return a handshake status within our 15-second socket window.
Rate Limiting / Throttling (ERR_PUBLIC_PLATFORM_THROTTLED_429):
ERR_PUBLIC_PLATFORM_THROTTLED_429
The Spanish government gateway returns an HTTP 429 status code due to high systemic transactional congestion.
Service Maintenance (ERR_SERVICE_UNAVAILABLE_503):
ERR_SERVICE_UNAVAILABLE_503
The public network infrastructure returns temporary maintenance windows.
3. Terminal Registration Errors (Non-Retryable)
These occur when an explicit structural rejection is sent back by the Spanish Public Platform during onboarding execution. Automatic retries will not resolve these states; human intervention is mandatory.
Unauthorized Certificate Signature (ERR_CERTIFICATE_UNAUTHORIZED):
ERR_CERTIFICATE_UNAUTHORIZED
The digital certificate is successfully read but lacks authorized administrative signing rights within AEAT for the specified company NIF.
Entity Registration Mismatch (ERR_REGISTRATION_REJECTED):
ERR_REGISTRATION_REJECTED
The tax authority rejects the onboarding request due to conflicting profile combinations (e.g., submitting a Business NIF mapped under a Sole Trader registry type).
State Machine Retry Mechanics
For all
Asynchronous Transient Errors
, the onboarding engine will avoid failing the onboarding pipeline outright. Instead, the account will transition through a managed recovery sequence:
json
[Valid Payload Received] 
           │
           ▼
[State: PENDING_REGISTRATION] ────► (Call Public Platform API)
           │                                 │
           │ (Success)                       │ (Transient Error Detected)
           ▼                                 ▼
[State: REGISTERED]              [State: REGISTRATION_QUEUED_RETRYING]
                                             │
                                             ├─► [Retry Strategy: Exponential Backoff]
                                             │
                                             ├─► (Success on Retry) ──► [State: REGISTERED]
                                             │
                                             └─► (Max Retries Exhausted) ─► [State: FAILED_CRITICAL]
Retry Algorithm Details
Mechanism:
Exponential backoff with random jitter applied to prevent synchronized request spikes hitting the public gateway.
Max Retry Limit:
5 attempts.
Backoff Cadence:
Base delay of t_0 = 10\text{ seconds}, doubling on each consecutive retryable error up to a hard cap of 15 minutes between attempts.
Fallback Resolution:
If the 5th attempt fails, the state machine will flag the registration as
FAILED_CRITICAL
and emit an asynchronous Webhook event to notify the consuming application.
Standardized Error Payload Schema -
DRAFT
All error responses from the onboarding endpoints must adhere to a standardized JSON schema. This ensures integrating developers can predictably parse programmatic error codes while passing localized diagnostic logs directly to end-users when desired.
Example: Validation Failure Payload (422 Unprocessable Entity)
json
{
  "status": 422,
  "error_code": "ERR_INVALID_TAX_ID",
  "message": "The provided tax identification string does not conform to Spanish NIF/NIE validation standards.",
  "timestamp": "2026-07-06T10:35:00Z",
  "path": "/api/v1/es/onboarding/profile",
  "details": [
    {
      "field": "organization.nif",
      "rejected_value": "B1234567X",
      "reason": "Checksum character mismatch. Verify the leading/trailing letter corresponds correctly to corporate registry parameters."
    }
  ]
}
