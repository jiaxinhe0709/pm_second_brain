# Sage current capabilities

## 1. Summary

- **EXISTING:** Customers and configured connector clients use the same invoice POST. The caller's configured client identity selects outbound or inbound processing; the invoice type alone does not select direction. Evidence: `network-eInvoicing/src/Common/Common.Application/Services/Direction/InvoiceDirectionResolver.cs:10–21`; `network-eInvoicing/src/Lambdas/UploadedInvoicesHandler/Handler/UploadedInvoices.cs:289–345`.
- **EXISTING:** Submission creates a Sage invoice resource and attachment upload URLs. After upload processing, Sage publishes a send request or a received notification. Evidence: `network-eInvoicing/src/Api/PostInvoicesHandler/Handler/PostInvoices.cs:84–115`; `network-eInvoicing/src/Lambdas/UploadedInvoicesHandler/Handler/UploadedInvoices.cs:299–345`.
- **EXISTING:** Dataset-scoped reads support invoice retrieval, filtered listing and status history. Notifications publish work requests and outcomes through an external Notifications client. Evidence: `network-eInvoicing/infra/lib/ProviderApiStack.ts:504–566`; `network-eInvoicing/src/Api/GetInvoiceHandler/Handler/GetInvoice.cs:155–199`; `network-eInvoicing/src/Common/Common.Services.Notifications/NotificationService.cs:33–165`.
- **EXISTING:** UBL parsing, Factur-X/CII-to-UBL processing and Factur-X generation are separate paths. `EInvoiceConverter` is a UBL parser and field extractor. Evidence: `network-eInvoicing/src/Common/Common.UblConverter/Services/EInvoiceConverter.cs:12–34`; `network-eInvoicing/src/Lambdas/FacturXProcessingHandler/Services/FacturXProcessingService.cs:41–77`; `network-eInvoicing/src/Api/GetInvoiceHandler/Handler/GetInvoice.cs:234–337`.
- **EXISTING / OPEN:** The generic status API accepts the known `Cancelled` code and can dispatch it as a status-change request. This does not establish external withdrawal or Spain cancellation. Evidence: `network-eInvoicing/src/Common/Common.Models/EInvoices/StatusList.cs:22–48`; `network-eInvoicing/src/Api/PostInvoiceStatusHandler/Validators/PostEinvoiceStatusRequestValidator.cs:19–37`; `feature-proposals/FP-SEI-002-global-api-submission-withdrawal.md:35–45`.
- **SPECIFIED / OPEN:** Spain NIF addressing, SPFE handling, separate public-copy results and rectification mappings remain proposals or qualification gaps in the inspected evidence. Evidence: `specs/invoice-sending/api-reference/SPEC-SEI-043-invoice-sending-api-reference.md:132–147`; `specs/SPEC-SEI-015-invoice-creation-solution-specification.md:304–308`.

**Review basis.** Read-only inspection on 23 November 2026: this repository at `216e8f0`; `C:\repos\network-eInvoicing` at `5684196c93e9a28a6c0dc3189fb6dae8eb64eb78`. Code citations use `network-eInvoicing/<path>:<line>`. Other paths are relative to this repository. No platform research, runtime calls, builds or tests were performed. No change is proposed here.

**Labels.** EXISTING means traced implementation in this checkout, not verified production deployment. SPECIFIED means documentation, contract or proposal evidence only. OPEN means the inspected material does not confirm the capability or its scope. An OPEN entry identifies the nearest relevant evidence and the missing proof; it is not a claim that no implementation exists elsewhere.
